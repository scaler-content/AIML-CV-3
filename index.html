01

The 10-class landmark problem

If a CNN has already learned useful visual features from millions of images, should we train all of those weights from zero for our small landmark dataset?

Imagine a landmark-recognition app. The training set has only about 70 images per class, across 10 landmark categories. A large CNN trained from scratch may struggle, because it must learn edges, textures, shapes and landmark-specific patterns from that small dataset.

Connecting to the overfitting lesson

High training accuracy is not enough. Transfer learning can improve sample efficiency, but it does not remove the need for validation, careful splits, or generalization checks.

02

What is transfer learning?

Transfer learning reuses knowledge learned on a source task to help solve a related target task.

  • Source task: classify many ImageNet categories.
  • Target task: classify 10 kinds of famous landmarks.
  • Reusable knowledge: early visual patterns such as edges, corners, textures, and shapes.
  • Task-specific part: the final classifier that maps features to the target landmark labels.

Visualizer · Reuse the backbone, swap the head

ImageNet images train a pretrained CNN. We keep the backbone and attach a new classifier head for 10 landmark classes.

Why does this help?

A CNN trained on a large dataset has already learned useful filters. Reusing those weights can:

  • reduce the amount of task-specific data needed;
  • shorten training time;
  • provide a stronger starting point than random initialization.
Important

Transfer learning is not guaranteed to win. It depends on the similarity between source and target images, data quality, preprocessing, and how the model is adapted.

Does a pretrained model already know the names of our 10 landmarks? No. Its original classifier predicts source-dataset classes, so we replace the final head to predict our target classes.

04

Two strategies: feature extraction vs. fine-tuning

Strategy 1 · Feature extraction
  • Keep the pretrained backbone frozen.
  • Train only the new classifier head.
  • Usually faster and less prone to overfitting on very small datasets.
  • A strong first baseline.
Strategy 2 · Fine-tuning
  • Start from pretrained weights.
  • Unfreeze some or all pretrained layers and continue training.
  • Can adapt features to the target domain.
  • Needs care: a small learning rate for pretrained layers, and monitor validation.

Preprocessing is part of the pretrained model

Resizing to 224×224 and converting to tensors is only the minimum. For an ImageNet-pretrained torchvision VGG16, use the model's expected preprocessing: resize/crop as its weights specify, then normalize the channels with the ImageNet mean and standard deviation.

Why does this matter? The pretrained model learned from inputs prepared in a particular way. Different scaling and normalization can shift the input distribution and reduce performance. The weights object supplies the recommended transform, which is safer than guessing.

07

Build the transfer-learning model

  1. Load pretrained VGG16 weights.
  2. Freeze the pretrained parameters.
  3. Replace the classifier so its output dimension equals the number of landmark classes.
  4. Train only the new classifier at first.

In PyTorch a frozen parameter has requires_grad = False; a new layer is trainable by default.

Visualizer · Anatomy of the adapted VGG16

Select a part to see what stayed, what changed, and how many parameters it holds.

  • Stayed the same: the pretrained convolutional feature extractor.
  • Changed: the final classifier, because the target task has a different number of classes.
  • Trainable: new classifier parameters.
  • Frozen: pretrained backbone parameters.

This head uses a small hidden layer and dropout. A single linear output layer is also a valid design; the small head is a teaching choice, not a guarantee of higher accuracy.

Code and output 
weights = models.VGG16_Weights.IMAGENET1K_V1
model = models.vgg16(weights=weights)

for param in model.parameters():
    param.requires_grad = False          # freeze

# VGG16's pooled feature vector has 512 * 7 * 7 = 25088 features for 224x224 inputs.
model.classifier = nn.Sequential(
    nn.Linear(25088, 512),
    nn.ReLU(inplace=True),
    nn.Dropout(p=0.3),
    nn.Linear(512, num_classes)
)
model = model.to(device)

Train the new head, use validation performance to monitor progress and choose the best checkpoint, and leave the test set untouched until the final evaluation. If the target dataset is small but similar to ImageNet, we expect faster convergence and better validation performance than scratch training. That is a hypothesis to test, not a guaranteed result.

def fit_model(model, train_loader, val_loader, epochs=5, lr=1e-3):
    criterion = nn.CrossEntropyLoss()
    optimizer = optim.Adam((p for p in model.parameters() if p.requires_grad), lr=lr)
    best_val_loss = float("inf"); best_state = None
    for epoch in range(epochs):
        train_loss, train_acc = run_epoch(model, train_loader, criterion, optimizer)
        val_loss, val_acc = run_epoch(model, val_loader, criterion)
        if val_loss < best_val_loss:
            best_val_loss = val_loss
            best_state = {k: v.detach().cpu().clone() for k, v in model.state_dict().items()}
    if best_state is not None:
        model.load_state_dict(best_state)

Fine-tuning: when the head is not enough

If the frozen feature extractor plateaus, some pretrained features may need to adapt to the target domain. Fine-tuning is the next experiment.

Safe fine-tuning recipe

  1. Unfreeze only the last convolutional block initially.
  2. Use a smaller learning rate for pretrained weights than for a newly initialized head.
  3. Monitor validation loss and accuracy.
  4. Keep the best validation checkpoint.
  5. Stop if validation performance deteriorates.

Visualizer · Two learning rates in one optimizer

Trainable parameters after unfreezing the last block (model.features[24:]): 19,930,122 = 12,850,698 (head) + 7,079,424 (last conv block).

Smaller steps for pretrained weights, because they already encode useful features and large updates can damage them.

Over three epochs validation accuracy moved 0.916 → 0.923 → 0.910 while training accuracy stayed at about 1.0. This was an optional run; compare against the frozen baseline and keep the best validation checkpoint.

Code 
for param in model.features.parameters():
    param.requires_grad = False
for param in model.features[24:].parameters():   # last VGG16 block
    param.requires_grad = True
for param in model.classifier.parameters():
    param.requires_grad = True

optimizer_finetune = optim.Adam([
    {"params": model.features[24:].parameters(), "lr": 1e-5},
    {"params": model.classifier.parameters(), "lr": 1e-4},
])

Troubleshooting transfer learning

Visualizer · Symptom → checks

Common implementation mistakes

  • Forgetting to replace the final classifier.
  • Forgetting to freeze parameters in feature-extraction mode.
  • Passing frozen parameters to the optimizer unnecessarily.
  • Using ImageNet weights with the wrong normalization.
  • Selecting hyperparameters based on test performance.
  • Assuming frozen weights mean the model needs no training; the new head still must learn.

Ask, challenge, verify

Scenario: a team has 700 labeled landmark images across 10 classes. Their VGG16 model reports:

Visualizer · Train vs. validation accuracy

Write your own diagnosis first. Then, if you ask an AI assistant for three plausible reasons why fine-tuning all VGG16 layers raised training accuracy but lowered validation accuracy (with one experiment for each), do not accept the answer automatically: mark each suggestion supported, plausible but unverified, or unsupported.

Reveal the expected direction

Overfitting is a leading hypothesis, but the curve alone does not prove the cause. Good controlled experiments: partial fine-tuning, lower learning rates, stronger training augmentation, and inspecting the split for duplicates.

Verification checklist

  • Does the explanation fit the train/validation pattern?
  • Does the proposed experiment change one major factor at a time?
  • Does it preserve the held-out test set?
  • Does it consider data leakage, learning rate, and number of trainable layers?
  • Is the AI claiming certainty from evidence that cannot prove the cause?
13

Interview case study: only 500 images

Case: a company has 500 labeled medical or industrial images and wants a custom classifier. A large CNN trained from scratch performs poorly. How would you approach it? Draft your plan, then open the strong answer.

Strong answer structure
  1. Verify labels, class balance, and train/validation/test separation.
  2. Start with a pretrained model from a reasonably relevant domain.
  3. Replace the classifier head with the target number of classes.
  4. Freeze the backbone and train the head as a baseline.
  5. Evaluate on validation data and inspect mistakes.
  6. Fine-tune selected layers with a small learning rate if needed.
  7. Report the final result on an untouched test set.
Follow-up: when might transfer learning help less?
  • When the source and target domains differ greatly.
  • When the pretrained model's input format is incompatible.
  • When labels or data splits are poor.
  • When the target task requires features not represented well by the source model.
